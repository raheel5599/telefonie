# TARIQ Telefonie · native Android/iOS app

Flutter 3.47.7 with native Kotlin AudioRecord/AudioTrack and Swift AVAudioEngine audio. No embedded website. Uses the existing authenticated Asterisk backend through HTTPS/WSS. PCM is 16 kHz, 16 bit, mono, 20 ms frames, matching the server's slin16 transport.

## Current test scope

- Same phone account login, session stored in OS secure storage; passwords are not saved.
- Dialpad, incoming/outgoing calls, internal extensions, echo test.
- Contacts, account-scoped persistent history, password change.
- Mute, speaker route, hold/resume, hold music/text selection, transfer with recovery.
- Foreground native test only. Incoming background/terminated-app ringing and lock-screen call acceptance require the next PushKit/CallKit and Android Telecom/FCM stage. The UI explicitly shows this limitation. Idle phones go offline when the app is backgrounded.
- iOS ongoing audio is configured as a background audio session, but actual interruption/headset/lock/background behavior must be verified on physical devices before production use.

## Reproduce a build

From mobile/: `flutter create --project-name tariq_telefonie --org de.tariqitconsulting --platforms android,ios .`, then `python3 -m pip install Pillow==11.3.0`, `python3 tool/prepare_native.py`, `flutter pub get`, `dart run flutter_launcher_icons`, `flutter test`, and `flutter build apk --release` or `flutter build ios --release --no-codesign` on macOS.

Platform folders are regenerated by the pinned Flutter SDK; native patches are retained under native/ and applied by prepare_native.py. Native bundle/application ID: de.tariqitconsulting.tariq_telefonie.

## Installation and credentials

The Android test APK uses Flutter's generated debug signing key, even in release mode, and is not a Play Store release. A later CI build may use a different temporary test key and require uninstalling the old test app. Store signing must use the owner's securely managed production key.

The iOS build is unsigned and cannot be installed on an iPhone as delivered. An Apple Developer team and provisioning/signing are required before TestFlight/device installation. No Apple or Google credentials are stored in the source. The microphone, routing and call lifecycle still require real Android and iPhone tests.

Backend changes introduce /api/native/login and accept bearer sessions only for explicitly native-issued sessions. All existing ownership, company selection, Origin, CSRF and call control validation remains in effect. Web sessions do not expose tokens.
